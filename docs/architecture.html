②两条运行路径：CLI 与 serve 共享同一个下载核心

⑤值得知道的几个事实

  • 下载历史只有一份：CLI 与 serve 都追加 $VYTDL_HOME/download_record.json（internal/record，带锁原子写）。vytdl.db 只是 serve 的实时队列（downloads / settings / vtt_reports 三张表），回答"历史上下过什么"要用 vYtDL records。
  • 领域类型长在 downloader 里：DownloadResult、ProgressUpdate 定义在 internal/downloader，导致 record 和 tui 反向依赖它——这是依赖表里两条"向上"的边。
  • server 是最大的包（3,327 行，约占 41%）：HTTP 装配、队列调度、SQLite、元数据、VTT 分析、音频提取都在一个包里，内部按文件分工（handlers / queue / database / hub / meta / vttanalyzer / audio）。
  • yt-dlp 永远是子进程：vYtDL 不重新实现下载 / 鉴权，cookie、proxy、user-agent、extractor-args 原样透传。yt-dlp 二进制由 internal/ytdlpbin 按序解析：显式路径 → PATH → 内嵌（-tags embed_ytdlp）→ ./bin/yt-dlp（缺失时自动下载的目标位置）→ 用户缓存目录旧副本。
  • 没有域名白名单：站点覆盖 = 当前 yt-dlp extractor 的覆盖；X/Twitter 单条推文自动 twitter:api=syndication，用户显式传 twitter:api= 时优先。
